# Canon: Terminologi

## Centrala termer

| Term | Definition | Användning |
|---|---|---|
| Börläge | Beskrivning av hur utvecklingsområdet bör fungera i ett framtida, beslutat eller rekommenderat läge. | Huvudterm i boken. |
| Nuläge | Beskrivning av hur arbetssätt, information, verktyg, teknik, resurser och regelverk fungerar i dag. | Används som jämförelsepunkt mot börläge. |
| Målbild | Övergripande riktning, effekt eller ambition. | Ska inte förväxlas med detaljerat börläge. |
| Färdplan | Översiktlig väg från nuläge till börläge. | Föredras framför roadmap i svensk löptext. |
| Övergångsarkitektur | Beskrivning av ett fungerande mellanläge på väg mot börläget. | Används när gamla och nya lösningar samexisterar. |
| Utvecklingsområde | Avgränsat organisatoriskt eller funktionellt område med ansvar för utveckling och förvaltning. | Skrivs med liten bokstav om det inte är egennamn. |
| Verksamhetsarkitekt | Roll som beskriver verksamhet, arbetssätt, förmågor, ansvar och information. | Skrivs med liten bokstav i löptext. |
| IT-arkitekt | Roll som beskriver tekniska strukturer, system, integrationer och tekniska vägval. | Behåll versalt IT. |
| Arkitekturperspektiv | Avgränsad vy av börläget, exempelvis information eller teknik. | Ska kopplas ihop med övriga perspektiv. |
| Gap | Skillnad mellan nuläge och börläge. | Ska alltid kopplas till konsekvens och möjlig åtgärd. |

## Skrivregler

- Använd `börläge`, inte `målarkitektur`, när boken avser målbilden för hela utvecklingsområdet.
- Använd `färdplan`, inte `roadmap`, om inte ordet roadmap förekommer i organisationens etablerade språk.
- Använd `övergångsarkitektur` för mellanlägen och `färdplan` för vägen mellan lägen.
- Skriv `verksamhetsarkitekt` med liten bokstav i löptext.
- Skriv `IT-arkitekt` med versalt IT.
